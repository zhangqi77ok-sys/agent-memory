# 第二十一轮设计：睡眠巩固（sleep consolidation）——已落地

定位：人脑在睡眠里巩固记忆——白天一起被想起的连接变强、无用的连接
淡出、重复的表述合并、同类经验抽象成原则。此前的巡检各有分工，
睡眠巩固不重复它们：
- consolidate（第十一轮起）：经验生命周期——衰减、合并、裁决、退役；
- weave（第十五轮）：新节点连边、补边、余弦簇抽象；
- 睡眠（本轮）：只从「使用证据」出发重组——共用、剪枝、事实合并、
  共用簇抽象。触发证据全部来自简报交付记录，不靠猜测。

## 四项任务（app/sleep.py::sleep_consolidate，每小时巡检节拍顺带跑）

每小时跑是安全的，因为每项任务自带门限，不会每小时重复做功：

1. **共用强化（Hebbian）**：同一份简报里一起递出的经验 = 一起被想起。
   窗口 = 自上次巩固报告以来新产生的交付（报告行本身就是水位）：
   窗口内同现的每对经验，若已有扩散边，按已验证的应用规则
   strength_on_applied 加一次（每边每轮只加一次，不按同现次数重复加）。
2. **共用建边**：全量交付里同现 ≥ 2 次的经验对、且目前无任何有效边，
   连一条 related 边（强度 0.5，origin=rule）——「一起被想到的经验先
   记相关」，与写入时织网「拿不准就先连 related」的哲学一致。
   每轮新建上限 50 条，按同现次数降序，先连最常一起出现的。
3. **死边剪除**：扩散边同时满足三条才关边（valid_to=now，关边可逆，
   日后织网补边能重新连上）：强度已到下限 0.10；自上次交付/结清/
   创建以来闲置 ≥ 3 整月；从未被证实应用过（无 applied 的交付边记录）。
   光被否决到下限但最近还在用、不剪；光闲置但强度未到下限、不剪。
4. **事实合并（睡眠档）**：事实此前没有合并巡检（写入时只做同主题同
   内容的佐证计数）。同用户、同主题、内容规范化相等或向量余弦 ≥ 0.95
   的有效事实对：保留置信度/佐证数/时间更优者，佐证数相加、置信度按
   support/(support+1) 重算，败者关行、边按 migrate_links 迁移（矛盾边
   关边，关联边改指保留行），留审计。跨主题事实不合并——事实以主题
   为键，跨主题同内容更可能是两回事（与经验跨主题合并的高门槛同理，
   但事实侧直接不做）。
5. **共用簇抽象**：全量同现 ≥ 2 次的边做并查集，簇规模 ≥ 3 且跨 ≥ 2 个
   项目、且尚无一条通用原则（project=None 的经验）经 generalizes 边
   覆盖其中 ≥ 2 名成员时，若配置了判定器，起草一条原则并连 generalizes
   边（与 weave 的余弦簇抽象同口径，但簇的来源是共用证据而非向量相似）。
   无判定器时本项为 0，不硬编自然语言（第二十轮设计已定此边界）。
   每轮最多起草 5 个簇，按簇规模降序。

## 巩固报告（consolidation_report，迁移 0021）

每用户每轮落一行（含全零行——零行本身就是水位，下一轮的共用窗口
从它起算）。字段：merged / merged_pairs（保留者与败者的 id 与主题）、
pruned / pruned_links、strengthened / strengthened_links、linked /
linked_ids（新建共用边）、generalized / generalized_ids（新原则的 id
与主题）。REST GET /v1/me/consolidation/latest、MCP
memory_consolidation_report、面板「睡眠巩固」一节都读最新一行。

## 与第二十轮的关系

- 共用强化复用 strength_on_applied（与回流/反馈同规则），不是新调参；
- 死边剪除接在闲置衰减（decay_idle_edges）之后：衰减把强度压到下限，
  剪除把长期无用的下限边关掉——衰减是淡出，剪除是断开；
- 报告行水位与 decayed_until 锚点同哲学：同一段历史只结一次账。

## 本轮不做的事

- 事实跨主题合并（见上）；偏好合并（偏好以 key 为键，写入时已处理）；
- 睡眠时重算全部边权（只动窗口内与死边两类，巡检成本有界）；
- 原则去重合并（两条近重复原则的合并留待后续轮次，与事实合并同
  手法，但原则是经验行，需先验证与 consolidate 的合并口径不冲突）。
